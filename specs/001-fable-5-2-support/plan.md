# Implementation Plan: Fable 5.2 AI Model Support

**Branch**: `001-fable-5-2-support` | **Date**: 2026-11-10 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-fable-5-2-support/spec.md`

## Summary

Replace Fable 5.1 with Fable 5.2 as the top selectable AI model. The API request stays the same apart from the model ID (research R1). A saved Fable 5.1 choice carries over through the existing `RETIRED_AI_MODELS` map (R3). Every user-facing and comment mention of Fable 5.1 is updated (R4). `@anthropic-ai/sdk` is upgraded from 0.129.0 to 1.7.0, which moves requests to API version `2026-10-21` and sends the key as `Authorization: Bearer`. The upgrade inventory found nothing in the code that the new version or SDK breaks (R2).

## Implementation Order

0. **SDK upgrade (its own commit)**: first write an offline wire test in `src/ai/client.test.ts` that stubs `globalThis.fetch` and asserts the default client sends `anthropic-version: 2026-10-21`, `Authorization: Bearer <key>`, no `x-api-key`, and the unchanged body. It fails on 0.129. Then `bun add @anthropic-ai/sdk@^1.7.0`, then `bun run typecheck && bun run test` *before* any model change. This separates SDK breakage from the model swap. Fix only what tsc or the tests report, within the change-5 list (R2).
1. **Tests (red)**: point `optionsTabHandlers.test.ts` and `client.test.ts` at `claude-fable-5-2`, and add a `store.test.ts` case where `claude-fable-5-1` loads as `claude-fable-5-2`. The cycle and carry-over tests fail. The client test may pass at runtime, but it fails tsc until the union changes.
2. **Source (green)**: update `types.ts`, `constants.ts` and `store.ts`.
3. **Comments and docs**: `client.ts` comments, `pict-docs.ts`, `README.md`, `docs/index.html`.
4. **Verify**: quickstart §0–§2, then the manual TUI check. The live request is optional and needs the user's OK.
5. **Review**: code and security review of the diff. Commit on a feature branch, since the work is currently on `main`.
